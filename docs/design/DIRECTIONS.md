# Playmakers (formerly Gallery) — UI design directions (static mocks, 1440×900)

All four mocks show the same content: score + clock, Analyst and Fan views on a shared clock, 2D pitch with numbered player dots, pass-difficulty arc, xG shot card, an insight with cited events, a control/momentum chart, a What-If win-probability card, a favourite-player tag, controls (seed, speed, language, favourite, start/pause), and an Agent Trace panel with up/recovering/fallback states and a Kill Tactics button. Clubs: Northbridge Rovers v Southport Athletic, 1–0 at 34:12.
Source: `<slug>/index.html` (generated by a.py–d.py + gen.py). Re-shoot with `node shot.js <slug>`.
None of them use: lime/neon accents, glow, gradients, emoji, uppercase letter-spaced eyebrow labels ("01 / GROUNDED"), decorative pills, or generic rounded dark cards.

## A. Matchday Paper (editorial / Swiss print) — `editorial.png`
- Mood: a match report in a quality newspaper's sport section. Calm, authoritative, reads as written by people.
- Palette: paper #F4F1EA, ink #1A1A1A, secondary text #6B665C, rules #CFC9BC, one accent vermilion #C8371D (live clock, arc, citations, alerts), ochre #8A6A12 for fallback.
- Type: Newsreader (serif; headlines, numbers) + Inter Tight (UI). Scale 12 / 13 / 18 / 21–24 / 40 (score).
- Grid: 40 px margins, 3 columns (1fr 1fr 300) split by hairline rules, no cards. Pitch is a line drawing; home players solid ink, away hollow.
- Components: score sits in the masthead like a headline; insights are headline + standfirst + "Cited events #0412…"; stats are a 4-up figure row; trace is a plain status list; Kill is an outlined red button.
- Why judges: it looks like journalism, which supports "explains why it matters" and trust/compliance. It's the most distinctive of the four and the least like a template.
- Risk: a light editorial look reads less like live TV in the demo video.

## B. Studio (broadcast graphics package) — `broadcast.png`
- Mood: a Sky/BT/Amazon-style match-night graphics package, restrained and dark.
- Palette: #0D0E10 background, #141518 panels, #222429 rules, text #ECECEC / #8C8F96, team colours Northbridge #1D3E9E and Southport #E1A100, status green #5BB974, red #E5484D.
- Type: Barlow Condensed 600–700 (score bug, headlines, numbers) + Barlow (body). Scale 12 / 13 / 19 / 24 / 32.
- Grid: 28 px margins, 3 columns, 16 px gutters. Square corners everywhere.
- Components: a real score bug (team blocks, white score, black clock), a lower third with a team-colour bar, a stat strip, a What-If bar with a marker for the original probability, square status pips in the trace.
- Why judges: it reads as "this goes on a broadcast", which hits the overlay brief and the Premier League audience directly. It also makes the strongest demo video.
- Risk: dark sports UIs are common, so the quality of the type and spacing has to carry it.

## C. Instrument (data terminal) — `terminal.png`
- Mood: Bloomberg/F1-timing-style instrument. Dense, monochrome, numbers first.
- Palette: #0A0A0A, 1 px #262626 grid, text #E8E8E8 / #7A7A7A, a single signal amber #FFB000.
- Type: JetBrains Mono (all numerals, logs, tables) + IBM Plex Sans Condensed (headlines). Scale 11.5 / 12 / 14 / 19–20 / 30.
- Grid: hard 1 px cell grid, no margins between regions, wireframe pitch.
- Components: a monospaced score line, an agent table (agent / state / p50 latency), a timestamped log, `src #0412` citations, an amber Run/Pause.
- Why judges: it shows off the agentic and observability depth, and looks like serious engineering.
- Risk: the fan side feels cold, which weakens the "two really different experiences" criterion.

## D. Calm (light product, Apple Sports-like) — `calm.png`
- Mood: a polished consumer app. Quiet, spacious and friendly.
- Palette: #F5F5F7 background, white cards (14 px radius), text #1D1D1F / #515154 / #86868B, Northbridge #1F3FA8, Southport #C98A00, status green #248A3D, amber #B25000, red #C4282D.
- Type: Inter 400/500/600 with tight tracking. Scale 12 / 13 / 17 / 20 / 28 / 46 (score).
- Grid: 32 px margins, 20 px gutters, a centred hero scoreline, and a full-width "Match so far" timeline.
- Components: a segmented Replay/About switch, a soft pale-green pitch, floating white chips for xG and pass difficulty, a progress track for What-If, a "Stop Tactics agent" button in soft red.
- Why judges: it's the friendliest for fans and the easiest to read in a video.
- Risk: it's closest to generic SaaS. It only works if spacing and type stay strict.

## Recommendation
**B (Studio) for the main app, with A's habits for the writing.** The brief is literally overlays beside a live match, and the judges will mostly see a video, so a believable broadcast package scores highest on UX/demo and fit to the brief. Borrow from A the headline + standfirst + citation structure for insights and the plain hairline-rule trace list. Use A (Matchday Paper) for the /about page so judges get a calm, readable explainer. If he prefers light mode, D is the safe alternative. C is best kept as an optional "engineering view" of the Agent Trace for the agentic-design part of the video.
